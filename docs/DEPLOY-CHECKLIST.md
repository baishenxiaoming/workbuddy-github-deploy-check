# 部署对照清单（31 步）

用于逐条核对 WorkBuddy ↔ GitHub 部署状态。`[自动]` 表示可由脚本或接口验证，`[人工]` 表示必须在网页端确认。

## 阶段 1：安装连接器并完成 OAuth 授权

| # | 步骤 | 判定标准 | 方式 |
| --- | --- | --- | --- |
| 1 | 打开「更多连接器」 | 进入完整连接器管理页 | 人工 |
| 2 | 定位 GitHub | 列表含 GitHub 卡片 | 人工 |
| 3 | 点击「连接」 | 出现「连接器 GitHub 已解锁」提示 | 人工 |
| 4 | 查看授权页 | 显示三项确认（验证身份 / 资源范围 / 代表你行动） | 人工 |
| 5 | 点击「授权」 | 跳转回 CodeBuddy 回调地址 | 人工 |
| 6 | 等待授权成功 | 出现授权成功页 | 人工 |
| 7 | 回到连接器列表 | GitHub 卡片绿点，`+` 变 `>` | 自动 |

## 阶段 2：GitHub 端安装 App 并配置权限（最常遗漏）

| # | 步骤 | 判定标准 | 方式 |
| --- | --- | --- | --- |
| 8 | 首次访问安全确认（如触发） | 完成 sudo 模式验证 | 人工 |
| 9 | 登录 GitHub（如 cookie 失效） | 进入登录后的应用页 | 人工 |
| 10 | 找到 CodeBuddy-Connector | 出现在「已安装的 GitHub Apps」 | 人工 |
| 11 | 检查授权应用列表 | 「授权的 GitHub Apps」与「授权的 OAuth 应用」各有记录 | 人工 |
| 12 | 配置权限 | Permissions 覆盖读写；Repository access = 所有存储库；已保存 | 人工 |

## 阶段 3：双重验证

| # | 步骤 | 判定标准 | 方式 |
| --- | --- | --- | --- |
| 13 | 进入代码开发模式 | 切换成功 | 人工 |
| 14 | 触发连接测试 | 模型调用 GitHub 接口 | 自动 |
| 15 | 输入检查提示词 | `检查GitHub连接状态，双向认证是否通过？仓库权限是否获取？` | 人工 |
| 16 | 输出检查报告 | ① 认证通过 ② 仓库权限已获取 ③ API 正常 | 自动 |

> 注意：第 16 步的「仓库权限」若账号下没有仓库，只能证明读通路，不能证明写权限。写权限必须靠一次真实写操作验证。

## 已知陷阱

- **403 `Resource not accessible by integration`**：GitHub App 安装令牌无法创建用户级仓库。读接口全绿也会遇到。必须走 gh CLI / OAuth 令牌。
- **绿灯不等于写权限**：连接器状态只反映 OAuth 是否解锁。
- **`Validation Failed` 搜索错误**：无仓库账号的正常表现，不要误判为认证失败。
